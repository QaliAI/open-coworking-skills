# Operator validation

Beta means the skill is complete and tested on synthetic data. It does not
mean an operator has used it. Stable requires that evidence. This program is
how the evidence is collected. It is not a marketing list.

## Who to ask first

Ask six kinds of operator, one person each is enough to start:

1. Independent, one location.
2. Multi-location.
3. Runs OfficeRnD.
4. Runs Nexudus.
5. Uses HubSpot for the pipeline.
6. Has a material virtual-office or mail book of business.

Do not ask them to upload a full member directory. Ask for the minimum
export the playbook names, after they run `coworking-pii-redactor` if the
file will leave their machine.

## Jobs to run

Use their words, then the playbook:

- "Where are we leaking money?"
- "Which leads need attention?"
- "What will become available in 90 days?"
- "Which renewals should we discuss?"
- "Are discounts making us look healthier than we are?"
- "Give me Monday's priorities."

## What to write down

For each job: usefulness, accuracy, how hard the export was, terminology
that confused them, a workflow they expected and did not find, an assumption
that was wrong, an integration they wanted, and whether they did anything
different the next week. A skill with no "what I did differently" note stays
beta.

## What not to collect

No government IDs, card numbers, or full inboxes. No testimonial invented
from a polite reply. No star request as the point of the conversation.
Feedback issues on the public repository are the record.
